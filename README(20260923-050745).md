## Overview

**JASS Legacy Software Lab** is a personal laboratory for preserving,
exploring, testing, and modernizing classic DOS and Windows business
software.

The lab keeps historically appropriate virtual machines available so
that legacy applications, databases, development tools, file formats,
and workflows can be studied in their original environment.

The purpose is both **software preservation** and **legacy-system
modernization**: understand the original system first, then build a safe
path toward Python, SQL, SQLite, PostgreSQL, and PySide6.

## Preservation Rules

1.  Keep legacy VMs isolated from the Internet where practical.
2.  Maintain clean backups of working machines.
3.  Clone a VM before risky experiments.
4.  Preserve original installation media.
5.  Do not modify a known-good baseline unnecessarily.
6.  Document hardware and disk geometry.
7.  Preserve original database files before conversion.
8.  Perform migration work on copies of legacy data.

### Golden Master Principle

``` text
             GOLDEN MASTER
                  │
          ┌───────┴───────┐
```

## Why This Lab Matters

Large amounts of business software created in the 1980s, 1990s, and
early 2000s were built around DOS, dBASE, Clipper, FoxPro, DBF, Paradox,
BDE, Visual Basic, and Delphi.

Organizations can still encounter these systems because they contain
years of accumulated business rules and historical data.

Understanding the original environment helps answer:

-   What did the original application actually do?
-   Where is the business logic?
-   Which database format does it use?
-   Which fields are authoritative?
-   Which calculations are embedded in the application?
-   What can be migrated safely?
-   What should be preserved?
-   What should be rewritten?

The lab bridges **legacy software archaeology** and **modern software
engineering**.
